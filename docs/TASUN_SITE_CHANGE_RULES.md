# Tasun 全站新增與修改規範

適用範圍：Wutasun/Tasun 全站頁面、前端程式、Worker/API、資料庫、權限、同步、GitHub Actions 與正式發布。  
生效日期：2026-11-19

## 一、基本原則

1. 以 GitHub 最新 main 為唯一實作基準；先確認使用者指定的頁面、網址與實際檔案，避免改錯相似名稱的頁面。
2. 一次只處理本次需求所需的範圍，採最小修改；相關的既有工作或資料不任意重做、刪除或覆蓋。
3. 維持 Tasun v5、TasunSelfHealV5、R268 自我修復、單一正式資料權威與「先去重、再同步」原則。
4. 除非需求明確要求，保留既有視覺、版面、主要操作、欄位、路由、資料格式及登入後操作習慣。
5. 新需求若與既有規則衝突，先列明影響和選項，不自行改變架構或擴大範圍。

## 二、功能與介面

1. 新增功能要沿用既有導覽、按鈕、表單、提示與錯誤處理方式；功能完成後，舊功能仍須可用。
2. 修改頁面前先確認桌面與手機版的版面和互動，不以單一螢幕尺寸判定完成。
3. 表格須保留必要欄位可見性、固定標題與選取行為；水平及垂直捲動都要可操作，資料更新不應任意把使用者帶回表格頂端或最左側。
4. 載入、登入橋接與雲端同步不得不必要地阻塞首屏和基本操作。能先顯示本機資料時，先完成畫面和事件綁定，再於背景同步。
5. 表格更新採批次繪製；隱藏檢視不重複建立；避免無界輪詢、重複請求、密集整頁重繪及會造成卡頓的同步工作。
6. 提示應清楚顯示載入中、成功、失敗或待同步狀態；錯誤不應讓按鈕失去操作能力，也不可用永久遮罩掩蓋頁面。

## 三、資料、登入與安全

1. 保留既有角色、帳號啟用狀態、權限繼承及後端授權判定；前端顯示或隱藏按鈕不能取代伺服器端權限檢查。
2. 不在 HTML、JavaScript、公開儲存庫、日誌或錯誤訊息中放入密碼、Token、密鑰或個人敏感資料。
3. 新增或修改資料欄位時，先確認所有讀取、寫入、匯入、匯出、備份及同步路徑；確保舊資料可讀且更新不會遺失資料。
4. SQL、資料庫結構、正式 D1 資料寫入或刪除、Worker 生產部署、密鑰操作及權限升降屬高影響操作。超出本次明確授權時，先停下並提供具體計畫，不自行執行。
5. 對輸入值做必要驗證；輸出 HTML 時避免未處理使用者輸入，並維持既有 CORS、登入與工作階段安全設定。
6. 不為了方便而新增第二套登入、權限、版本或資料權威；優先沿用專案既有來源與 API。

## 四、程式修改與檢查

1. 先查清楚問題根因和受影響檔案，再做最小補正；不以重寫整頁處理局部問題。
2. 驗收條件要能觀察和重現，例如：首屏可操作、同步不阻塞、表格雙向捲動正常、登入與權限維持正確。
3. 依修改風險執行相符檢查：至少檢查語法與差異；前端、權限或同步變更執行相關回歸檢查；正式發布依現有 workflow 完成版本鏈與部署驗證。
4. 若 CI 或檢查失敗，先查根因；修正仍在已授權範圍內時可接續處理並重跑受影響檢查。若發現資料遺失風險、架構假設錯誤或必須擴大範圍，停止並回報。
5. 不宣稱已完成瀏覽器實測、正式資料驗證或部署，除非有相應證據。

## 五、GitHub 與正式發布

1. 功能修改從最新 main 建立獨立分支，提交精確變更並開 Pull Request；不直接覆寫 main，也不把未相關的修改混入同一 PR。
2. 等待必要 CI 通過，確認變更範圍正確且沒有未解決的阻擋項，再依專案流程合併。
3. 正式版本只以 tasun-version.json 及既有發布 workflow 為權威；不手動編造版本號、releaseSequence、HTML 版本戳或雜湊值。
4. Pages 網站修改走既有 GitHub Pages 發布流程；Worker、D1 與 Pages 是不同發布範圍，不能因修改靜態頁而順帶部署 Worker 或操作正式 D1。
5. 一般已授權的網站修正完成後，依流程自動同步至 GitHub、通過檢查後合併並確認正式發布；使用者不必下載 HTML 再手動上傳。
6. 發布後核對正式 workflow、部署結果、版本號及實際頁面網址；如只更新文件且不觸發網站發布，應清楚標明文件已上傳、網站未重新部署。

## 六、必須停下回報的情況

遇到下列情況，不默默擴大修改或越權操作：

- 需要變更登入架構、角色權限、API 契約、主要資料格式或資料庫結構。
- 可能造成正式資料刪除、覆蓋、重複或無法回復。
- 需要修改 Worker 生產環境、正式 D1、密鑰、DNS、Access 或外部付費資源。
- 最新 main 與需求衝突、CI 阻擋無法在本次範圍修復、或頁面/資料來源無法確認。
- 需求本身有多種會影響使用方式或資料安全的方案，需要使用者選擇。

## 七、每次完成時的回報

用簡短文字列出：修改頁面/檔案、變更重點、檢查或 CI 結果、PR/提交與發布狀態、正式版號及網址。尚未確認的部分標示待確認，不把預期結果說成已驗證結果。

## 可直接複製的口語指令

請依《Tasun 全站新增與修改規範》處理以下需求：

需求：［描述要新增或修正的功能］  
目標頁面或檔案：［填入檔名或網址；不確定時先比對實際頁面］  
驗收方式：［描述完成後要能看到或操作的結果］

請先以最新 main 確認影響範圍，採最小修改並保留既有介面、資料、登入權限及其他功能。依需求完成檢查與必要回歸；在已授權範圍內，自動建立分支與 PR、等待 CI、依流程合併，並使用正式 GitHub workflow 發布 Pages 網站。完成後回報 PR、檢查結果、正式版號及網址，不要要求我下載 HTML 再手動上傳。

若工作需要改登入/權限架構、正式 D1/Worker、密鑰、資料庫結構，或可能造成正式資料不可回復，請先停止並提出具體影響與處理方案。
